# Result Mode — Памятка для Lead'а

## Идея

Один умный Claude Code заменяет 3 роли (Analyst/Developer/QA). Источник задач — `BACKLOG.md` в корне репозитория. Никакой Jira.

## Setup (один раз)

1. Положи `CLAUDE.md` в корень `D:\Projects\MyFit-Android\`
   (Не в подпапку `MyFit-team\`, а прямо в репозиторий — агент будет жить в проекте.)
2. Положи `BACKLOG.md` туда же.
3. Закоммить и запушь оба файла:
   ```powershell
   cd D:\Projects\MyFit-Android
   git add CLAUDE.md BACKLOG.md
   git commit -m "chore: introduce result-mode with BACKLOG.md"
   git push
   ```
4. **Опционально:** старые папки `D:\Projects\MyFit-team\analyst\`, `developer\`, `qa\`, `architect\` оставить как архив — мало ли пригодятся.

## Запуск рабочей сессии

```powershell
cd D:\Projects\MyFit-Android
claude
```

Первая команда в сессии:

```
Прочитай CLAUDE.md и BACKLOG.md. Покажи 3 ближайших [ ] задачи и предложи, с какой начать.
```

Агент покажет варианты, ты выбираешь, дальше работа идёт по workflow из CLAUDE.md.

## Типовые команды

**Начать задачу:**
```
Бери B-1. Покажи план перед началом.
```

**Проверить статус:**
```
В каком статусе текущая задача? Что осталось до PR?
```

**Дать обратную связь по плану:**
```
План ок, приступай. Только: <уточнение>
```

**Пауза:**
```
Стоп. Сохрани текущий прогресс, скажи, на каком моменте остановились.
```

**Возврат после паузы (в новой сессии):**
```
Прочитай BACKLOG.md и последний git log. Скажи, на чём остановились в прошлый раз.
```

## Тестирование на устройстве

Это **остаётся за тобой**. Агент не может прокликать APK.

После того, как агент создал PR:

1. Подтяни ветку в Android Studio: `View → Tool Windows → Git → Branches → checkout feature/B-N-...`
2. Нажми ▶ Run
3. Пройди по golden path из описания PR
4. Сравни с PWA, если применимо

Если всё ок:

```
Всё проверил, ок. Merge PR и обнови BACKLOG.md.
```

Если есть замечания:

```
Нашёл проблемы: <список>. Поправь.
```

## Бэкап БД перед миграциями

Когда агент скажет «следующий шаг — миграция БД», сделай:

```powershell
adb shell run-as com.maxshpl.myfit cp databases/myfit.db /sdcard/myfit-pre-BN.db
adb pull /sdcard/myfit-pre-BN.db D:\Projects\MyFit-Android\backups\myfit-pre-BN.db
```

(Заменяя `BN` на номер задачи, например `B1`.)

## Когда агент должен останавливаться (по CLAUDE.md)

- Требования неясны
- Нужно архитектурное решение
- Расхождение между BACKLOG и кодом
- Сборка ломается, фикс не очевиден
- Хочется scope creep
- Миграция БД (нужен бэкап)

Если он останавливается и спрашивает — отвечай. Если он сам решает спорный момент **без** вопроса — это сигнал что-то поправить в CLAUDE.md.

## Что НЕ делаем больше

- Не пишем в Jira (старая Jira-история — архив).
- Не обновляем Confluence Space MyFit (он застыл в состоянии после KAN-17).
- Не запускаем три отдельных окна для Analyst/Developer/QA.
- Не делаем pre-review smoke-test перед формальным QA — теперь нет формального QA, есть только твоя проверка после PR.

## Что добавляем в BACKLOG со временем

- Найденные баги (`B-bug-N`)
- Новые идеи (`B-idea-N` или просто добавить в "Идеи на будущее")
- Замечания после ручной проверки, если выходят за scope текущей задачи

## Метрики (опционально)

В конце каждой закрытой задачи можешь записывать в `BACKLOG.md` короткую заметку:
- Время от старта до merge (часы активной работы Lead'а)
- Сколько раз агент останавливался спросить
- Замечания после ручной проверки (были / не было)

Через 5-10 закрытых задач увидишь паттерны: где агент сильнее, где слабее.

## Когда стоит вернуться к 3-ролевой схеме

Маркеры, что result-mode не справляется:
- Регулярные регрессии в работающих модулях
- Сложные тикеты (Health Connect) — агент теряется в большом контексте
- PR-ы стали "монолитными", сложно ревьюить
- Чувствуешь, что качество стало хуже

Тогда возвращай Analyst+Developer+QA для конкретного сложного тикета, а простые продолжай в result-mode.
